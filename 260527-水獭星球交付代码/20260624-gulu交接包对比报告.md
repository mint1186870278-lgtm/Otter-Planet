## 一、⚠️ 重磅未文档化变更：新增「用户注册/登录系统」

新增两个文件并已接入 `index.html`：
- `otterlantis-auth.js`（339 行）
- `otterlantis-auth.css`
- index.html 引用：`?v=20260622-users`

**619 包和现有 dist 都没有它**，是这次真正的新功能。

### 它做了什么
- **进游戏前强制弹全屏登录遮罩**：`.otter-auth-overlay`（`position:fixed; inset:0; z-index:9999`）+ `.otter-auth-lock`（`overflow:hidden` 锁住页面）。未登录会被挡住，无法直接玩。
- **三种身份流程**：
  1. 已有 ID → 输入 `OT-XXXXX` 登录（`GET /api/users/{id}`）。
  2. 注册「勇敢的水獭」(child) → 只填昵称，默认随机昵称，提示"不要用真实姓名"（`POST /api/users {role:"child", displayName, lang}`）。
  3. 注册「家长」(guardian) → 填显示名 + 邮箱，说明里写明"MVP 先记邮箱，验证码下一步再接"（`POST /api/users {role:"guardian", displayName, email, lang}`）。
- 登录成功 `releaseGame()` 移除遮罩，发埋点 `game_start_after_register`。
- **右侧常驻账号切换器**：显示当前角色(家长/水獭)+ID + "切换 ID"按钮（清除本地用户并 reload）。
- **本地存储**：`localStorage` 存 `otterlantis_user` 和 `otterlantis_session_id`（`sess_*`），不持久化到服务器以外。
- **埋点注入**：用 monkey-patch 包了全局 `window.fetch`，凡是发往 `/api/track` 的请求自动塞入 `otterId` 和 `userRole`。**这直接关系看板数据结构**——后续看板要能按用户/角色聚合。

### 评估要点（需要你和后端确认）
1. **接口依赖**：依赖后端 `/api/users`、`/api/users/{id}`、`/api/track` 三个接口必须就绪且走 HTTPS。`/api/users` 在历史接口清单里没有，**需确认后端是否已实现**，否则注册/登录会直接失败、卡在遮罩进不了游戏。
2. **儿童产品合规**：guardian 流程收集**邮箱**（PII），且明说验证码"下一步再接"=当前**无任何验证**。儿童产品收集家长邮箱需评估隐私合规（COPPA/个人信息保护）。child 流程已做"勿用真名"提示，较稳妥。
3. **体验风险**：5–7 岁产品在游戏前加强制注册墙，会显著抬高跳出率。要确认这是产品决策还是前端自行加的。
4. **版本号不一致**：auth 文件挂 `?v=20260622-users`，主包是 `20260624-gulu`。随包的版本一致性检查脚本 `check-retellfix-version-consistency.js` **只校验 5 个核心文件，不含 auth**，所以 auth 的旧版本号不会被发现。上线时注意 auth 改动后手动升版本号，避免 CDN 缓存旧 auth。

## 四、部署建议

1. **先和后端确认 `/api/users` 系列接口已上线且走 HTTPS**，否则注册墙会把所有人挡在门外。
2. **产品侧拍板**：是否真要在 5–7 岁游戏前加强制注册墙；guardian 邮箱收集的合规问题要过一遍。

4. auth 文件后续修改记得手动升 `?v=`，它不在一致性检查脚本覆盖范围内。
5. 上线前跑随包脚本：`node scripts/check-story-retell-fixes.js`、`check-retellfix-version-consistency.js`、`check-tutorial-build.js`，外加 `node --check` 三个 JS。
