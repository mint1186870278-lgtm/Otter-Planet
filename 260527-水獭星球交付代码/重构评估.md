# 水獭星球跑酷场景 — 现状报告 & 「跑道式 → 真开放世界」改造评估

> 评估日期：2026-05-30
> 评估对象：[src/components/ParkourScene.tsx](src/components/ParkourScene.tsx)（524 行）、[src/components/SectionParkour.tsx](src/components/SectionParkour.tsx)（615 行）
> 配套文档：改造落地步骤见 [重构方案.md](重构方案.md)

## 结论先行

这套代码目前是**三车道无限跑酷（endless runner）**，不是开放世界。玩家钉死在 `z=2.5`、只能在 3 个离散车道间横移，所谓"前进"是整个世界沿 +z 滚动。

- **3D 场景层（ParkourScene）**几乎完全建立在"玩家不动、世界移动"这个假设上，改造伤筋动骨。
- **UI / 对话 / 计分层（SectionParkour 的大部分）**与移动范式解耦，可基本原样保留。
- **整体工作量：大。** 但不是从零重写——游戏逻辑层和 UI 层（占 SectionParkour 八成）大量可复用。

## 1. 移动系统现状

### 玩家位置如何被"固定"
- 玩家模型钉在 [ParkourScene.tsx:173](src/components/ParkourScene.tsx#L173)：`position={[0, 0, 2.5]}`，**z 永远是 2.5，从不改变**。
- 唯一会动的是 x 轴，且是离散"车道"：[ParkourScene.tsx:151](src/components/ParkourScene.tsx#L151) `targetX = lerp(targetX, lane * LANE_SPACING, …)`，`LANE_SPACING = 2.2`（[:7](src/components/ParkourScene.tsx#L7)）。
- `lane` 只有 `-1 / 0 / 1` 三个值，来自 SectionParkour 的 `position` state，左右键 `Math.max/min(p±1, ∓1)` 夹死在三档（[SectionParkour.tsx:111-112](src/components/SectionParkour.tsx#L111)）。
- **玩家没有真正的世界坐标**——它的"位置"只是一个 `-1/0/1` 枚举 + 一个固定 z。

### 依赖「玩家不动、世界移动」的逻辑（骨架假设）
| 模块 | 依赖点 |
|---|---|
| 地形 | 两块 tile 沿 +z 滚动，越过 `TERRAIN_LENGTH=120` 就 `-=240` 循环（[:42-48](src/components/ParkourScene.tsx#L42)） |
| 星星组 | 整组 `position.z += speed*d`（[:397-401](src/components/ParkourScene.tsx#L397)） |
| NPC 组 | 整组 `position.z += speed*d`（[:374-377](src/components/ParkourScene.tsx#L374)） |
| 障碍物 | `position.z += (terrainSpeed+obstacleSpeed)*d`（[:282](src/components/ParkourScene.tsx#L282)） |
| Debug 追踪 | 同步滚动 + 循环，算 NPC 世界 z（[:414-433](src/components/ParkourScene.tsx#L414)） |
| 全部碰撞 | 靠"物体滚到固定 PLAYER_Z 附近"判定（见 §4） |
| 相机 | z 永远 11，因为玩家从不前进（见 §2） |

### 所有用到速度 / 滚动的地方
- 定义：`SCENE_SPEED=8`、`OBSTACLE_SPEED=4`（[SectionParkour.tsx:9-10](src/components/SectionParkour.tsx#L9)），`ITEM_SPAWN_Z=-48`（[:8](src/components/SectionParkour.tsx#L8)）。
- `forwardSpeed` state 由 W/S/↑/↓ 驱动：前进 `+8`，后退 `-4`，松手 `0`（[:88-93](src/components/SectionParkour.tsx#L88)）。
- 透传链路：`forwardSpeed` → prop `terrainSpeed`（[:479](src/components/SectionParkour.tsx#L479)） → 喂给 TerrainModel / StarsGroup / NpcGroup / DebugNpcTracker / ObstacleObject 五处 `useFrame`。
- 障碍物特殊：即使玩家停下（`terrainSpeed=0`），障碍仍以 `obstacleSpeed` 主动冲向玩家——典型 runner 设计。
- **已有小不一致**：倒退（S）会让世界反向滚，但 NPC 一旦 `passed`（worldZ>8）就 `visible=false` 不可逆（[:351-354](src/components/ParkourScene.tsx#L351)），倒退不会重现。开放世界里这类"经过即消失"全要重做。

## 2. 摄像机系统

### 当前定位与跟随
- 初始 `camera={{ position: [0, 5.5, 11], fov: 70 }}`（[SectionParkour.tsx:472](src/components/SectionParkour.tsx#L472)）。
- 每帧由 `CameraRig` 重设（[:436-445](src/components/ParkourScene.tsx#L436)）：
  - `camera.position.set(tx, 5.5, 11)` — **高度 5.5、距离 11 写死**，`tx` 只跟车道做 `laneX*0.35` 轻微横移。
  - `camera.lookAt(tx*0.1, 0, -15)` — 永远望向前方固定点。
- 相机**完全不跟随前进**（因为玩家不前进），只在三车道间轻微左右倾。

### 改成跟随自由移动玩家要改的
- 需要拿到玩家**真实世界坐标**（目前不存在，见 §1），做经典第三人称跟随：`camera.position = playerPos + 偏移向量`，`lookAt(playerPos)`。
- 玩家能转向后，偏移向量需绕玩家朝向旋转（否则掉头时镜头穿模）。
- 整个 `CameraRig` 基本重写；`tx*0.35 / lookAt(-15)` 这套车道逻辑作废。
- **改动量：中**（单一组件，但要配合新的玩家坐标系）。

## 3. 物体定位

| 物体 | 当前坐标系 | 数据 |
|---|---|---|
| 星星 | **相对滚动**：`{lane, z}` 放进 StarsGroup，组整体往 +z 滚 | `STAR_POSITIONS` 15 颗，`lane∈{-1,0,1}`，z 从 -81 到 -435（[:187-206](src/components/ParkourScene.tsx#L187)） |
| 障碍物 | **相对滚动**：动态生成，从 `ITEM_SPAWN_Z=-48` 滚向玩家 | 每 2.5s 随机 `{variant, lane}`，7s 后清除（[SectionParkour.tsx:143-156](src/components/SectionParkour.tsx#L143)） |
| NPC | **相对滚动**：`NPC_LOCAL_Z=[-165,-294,-423]`，`sideX=3.5`，在 NpcGroup 里滚（[:305](src/components/ParkourScene.tsx#L305)，[:379](src/components/ParkourScene.tsx#L379)） |
| 云 | **独立装饰**：仅 x 轴横向飘动循环，与前进无关（[:87-103](src/components/ParkourScene.tsx#L87)） |
| 地形 | **循环 tile**：两块 120 长度无缝拼接 |

> **问号箱未实现**：`StaticCollectible` 的 type 只有 `'star'`，但 HUD 提到"问号箱解锁角色"（[SectionParkour.tsx:570](src/components/SectionParkour.tsx#L570)）、hitEffect 有 `'question'` 分支——3D 里尚未实现，是规划占位。

### 改成地图固定点要动的
- 星星/NPC：`{lane, z}` → `{x, z}` 世界绝对坐标，去掉所属 Group 的滚动 `useFrame`，直接定位。`STAR_POSITIONS` 数据结构和坐标全部要重排（15 颗手摆）。
- 障碍物：从"定时生成→滚动→超时销毁"改为地图固定布置（或玩家周围动态生成）；现有 spawn/清除定时器逻辑作废。
- 云：可原样保留。
- **改动量：中**（逻辑不难，但数据要重新设计 + 三个 Group 的滚动剥离）。

## 4. 碰撞检测

### 当前实现 — 全是「1D z 距离 + 离散车道匹配」
| 类型 | 判定 | 位置 |
|---|---|---|
| 星星收集 | `abs(worldZ - 2.5) < 1.2 && laneRef === item.lane` | [:232](src/components/ParkourScene.tsx#L232) |
| 障碍命中 | `2.5-0.8 ≤ z ≤ 2.5+0.8 && laneRef === obstacle.lane` | [:284-285](src/components/ParkourScene.tsx#L284) |
| NPC 接近 | `abs(worldZ - 2.5) < 6` | [:347](src/components/ParkourScene.tsx#L347) |

共同点：都假设玩家在固定 `PLAYER_Z=2.5`，只比 z 轴一维距离，x 方向靠**车道枚举相等**判断，**完全没有真正的平面距离**。

### 改成平面自由移动后
- 三处都要改成**玩家世界坐标 ↔ 物体世界坐标的 2D 平面距离**：`dist²=(px-ox)²+(pz-oz)² < r²`，丢掉 `laneRef === lane` 离散匹配。
- 玩家需先有真实坐标（§1 前提）。
- 物体多了之后，逐帧 N×M 距离判断可能要加空间划分（网格/四叉树），但中小地图先暴力遍历也能跑。
- **改动量：中**（模式统一、改写量不大，但前置依赖玩家坐标系 + 物体固定坐标这两个大改）。

## 5. 耦合度评估

### 🔴 与「假开放世界」深度耦合 — 改动伤筋动骨
- **Character**：固定 z、车道 lerp、朝向写死 `rotation=[0,π,0]`（[:173](src/components/ParkourScene.tsx#L173)）。
- **CameraRig**：整套围绕固定相机 + 车道横移。
- **TerrainModel / TerrainTile**：循环滚动是核心。
- **StarsGroup / NpcGroup / ObstacleObject / DebugNpcTracker**：全靠 `position.z += speed*d`。
- **全部碰撞检测**：1D + 车道。
- **输入系统**（[SectionParkour.tsx:88-128](src/components/SectionParkour.tsx#L88)）：左右切道 + 前进驱动滚动速度，`position(-1/0/1)` 模型。
- **ParkourScene props 接口**（[:448-462](src/components/ParkourScene.tsx#L448)）：`lane/laneRef/terrainSpeed/obstacleSpeed` 这套词汇本身就是跑道范式。

### 🟢 与移动范式解耦 — 可原样 / 几乎原样保留
- **全部 2D HUD**：星星进度条 + 图标动画 + milestone 刻度（[SectionParkour.tsx:277-345](src/components/SectionParkour.tsx#L277)）、提示卡、控制提示。
- **倒计时系统**（[:69-86](src/components/SectionParkour.tsx#L69)）。
- **NPC 对话 UI**（全屏 visual novel：立绘 / 打字机 / Mic / 继续）（[:387-467](src/components/SectionParkour.tsx#L387)）。
- **NPC 气泡（情况B）、去找伙伴提示（情况C）、hit flash 覆盖层**。
- **计分 / 里程碑 / NPC 对话触发判断**：`starCount`、`triggerMilestone`、`handleNpcApproach` 里 A/B/C 三档星星判断（[:175-201](src/components/SectionParkour.tsx#L175)）——**判断本身保留**，只是触发方式（不再靠滚动接近）要换。
- **模型加载基建**：`useGLTF` / `SkeletonUtils.clone` / 动画 mixer / 预加载——保留；Character 跑步动画 play/pause 思路保留，触发条件 `moving` 改为"是否在位移"。
- **云、光照、fog、背景色**：保留。
- **语言切换、NPC_DATA、移动端按钮容器**（按钮要换成新移动控制）。

## 6. 工作量预估

### 必须重写
| 项 | 说明 |
|---|---|
| 玩家移动 | 三车道枚举 → XZ 平面连续位移；新增真实坐标、八向输入、朝向随移动方向旋转 |
| 相机 | 固定机位 → 跟随玩家世界坐标的第三人称相机（随朝向旋转） |
| 地形 | 两块循环 tile → 固定大地图（或 chunk 加载），`TERRAIN_LENGTH` 循环作废 |
| 滚动剥离 | 星星/NPC/障碍/Debug 四组的 `position.z += speed*d` 全删，物体改世界固定坐标 |
| 碰撞 | 1D+车道 → 2D 平面距离（三处） |

### 需要调整
- 输入处理：`position(-1/0/1)` + `forwardSpeed` → 速度向量 / 连续坐标（[SectionParkour.tsx:88-128](src/components/SectionParkour.tsx#L88)）。
- `ParkourScene` props 接口重新设计（传 playerPos 而非 lane/terrainSpeed）。
- 障碍物生成：定时滚动 → 地图固定点或玩家周围生成（[:143-156](src/components/SectionParkour.tsx#L143)）。
- NPC 接近触发：从"滚到身边" → "玩家走进半径"（逻辑判断可复用，数据源换）。
- Debug 面板（PlayerZ 写死 2.5）、移动端按钮、Character 受击抖动。

### 可保留（改动极小或零）
- 全部 HUD / 倒计时 / NPC 对话 / 气泡 / 提示 / hit flash / 计分 & 里程碑逻辑 / 模型加载 & 动画基建 / 云 / 光照。

### 改动量评估

| 文件 | 重写比例 | 评级 |
|---|---|---|
| [ParkourScene.tsx](src/components/ParkourScene.tsx)（524 行） | ~70% 重写/大改（移动+相机+地形+滚动+碰撞）；~30% 保留（模型加载、动画、云、光照、模型子组件） | **大** |
| [SectionParkour.tsx](src/components/SectionParkour.tsx)（615 行） | ~20% 改（输入、props、障碍生成、debug、移动端按钮）；~80% 保留（HUD/对话/计分/UI） | **中→小** |

**总体：大。** 3D 核心循环（玩家不动+世界滚+1D碰撞+固定相机）是整个场景的承重墙，几乎要拆到地基重建；但游戏逻辑层（计分/里程碑/NPC对话判断）和 UI 层（占 SectionParkour 八成）大量可直接复用，**不是从零重写**。

务实路径：先给玩家加真实坐标 + 跟随相机（打通"玩家真的在动"），再把物体钉到世界固定坐标 + 换 2D 碰撞，UI 层基本不碰。详见 [重构方案.md](重构方案.md)。
