#### `?lang=` 双 URL 部署评估（zh / en 同一份包）

部署方案：`https://play.otterlantis.com/?lang=zh` 与 `?lang=en` 指向**同一份构建**，无需分别打包。机制健全，可用，但有几点必须知道：

- **判定规则**：只有 `?lang=en`（大小写不敏感，`EN`/`En` 都行）走英文；**其它任何值或缺省一律回退中文**。即裸 `https://play.otterlantis.com/`（无参数）= 中文。
- **来源单一且同步**：lang 只在主包初始化时从 URL 读一次 → `history.replaceState` 把参数写回地址栏 → 派发 `otterlantis:lang-change` 事件。跑酷子包**不自己读 URL**，靠主包以 `lang:a` props 传入，全站语言一致，不会两套各读各的。
- **不持久化**：没有 localStorage/cookie 记忆。用户刷新若 URL 仍带参数则保持；一旦参数被抹掉（手输裸域名、外部链接没带参）即回中文。SPA 内部跳转因 `replaceState` 会保留参数，单次会话内稳定。
- **SEO/分享提示**：语言纯前端 JS 决定，两个 URL 返回的 HTML 完全相同。爬虫/社媒预览拿到的是同一份源码，靠 `<meta>` 区分语言的方案这里不成立。若要 SEO 区分需另做 SSR/预渲染（当前未做）。
- **建议**：对外英文入口务必带全 `?lang=en`；可在落地处做一次性引导（或后续补 localStorage 记忆），避免用户刷掉参数后默默回中文。
