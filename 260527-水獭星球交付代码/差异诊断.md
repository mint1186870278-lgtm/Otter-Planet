## 建议修改顺序（按依赖关系）

**第 1 梯队 · 状态地基（无前置依赖，先做）**
1. **星星语义重构**：`starCount` → `totalCollected`（只增不减）+ 删障碍扣星（[:219](src/components/SectionParkour.tsx#L219)）+ 删 score 文案 + 进度条改"当前段/3"。最底层，第三/四/七章全依赖。
2. **新增 `npc1/2/3Done` + `npc2Name` 状态**：情况A/C 区分、结局完整度、假月亮过场都依赖。

**第 2 梯队 · 不依赖 AI 的规则逻辑（可并行）**
3. **障碍眩晕系统**：加 stun 锁输入 1 秒 + 抖动闪烁。
4. **NPC 情况 A/C 分流**：基于②的 Done 标记 + hardcode 三句催促。
5. **集齐中央弹窗重做**：基于①的分段进度。

**第 3 梯队 · 串联过场与结局（依赖第1/2梯队状态）**
6. **假月亮过场**：依赖 `npc2Done`。
7. **真月亮 + 升起动画 + 跳转结算**：依赖 `npc3Done`，打通 [:453-455](src/components/SectionParkour.tsx#L453) TODO。
8. **结局完整度系统**：依赖全部 Done + 第7步通路，改造 SectionResult。
9. **SectionIntro 台词**：纯文案，无代码依赖，收尾做。

**第 4 梯队 · 独立重模块（可全程并行，最耗时）**
10. **AI 对话接入**：阶跃星辰 API + System Prompt + `[COMPLETE]`/`[NAME]` 解析 + NPC3 开场补全。技术上只依赖"对话框已打开"，但标记解析要回写 ②的 Done/npc2Name，接入点等②就位。

> **一句话路线**：先钉死"星星只增不减 + Done 状态"两块地基（第1梯队），其余规则/过场/结局顺着状态往上长，AI 作为独立重模块并行、最后在标记解析处汇合。
>
> ⚠️ 前提：定稿描述的是**开放世界**玩法。若仍在跑道式上做，"跑过头补星""回头找漏掉 NPC"会别扭甚至无法成立（见定稿附表）。建议先确认是否同步推进 [MVP评估.md](MVP评估.md) 的开放世界重构——否则第①(补星)、第九章(漏NPC缺页)会与单向滚动逻辑打架。
