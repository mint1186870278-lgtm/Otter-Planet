## 一、改造结论

本次注册登录界面建议做「低风险视觉重做 + 小流程重排」，不迁移 React，不新增后端能力，不重写业务逻辑。

核心方向：

1. 保留当前原生 JS/CSS 浮层架构：`public/otterlantis-auth.js` + `public/otterlantis-auth.css`。
2. 保留现有接口：登录 `GET /api/users/{otterId}`，注册 `POST /api/users`，埋点 `POST /api/track`。
3. 未登录用户默认先进入「身份选择页」，再进入「小朋友注册」或「家长注册」。
4. 已有 ID 用户通过「已有 ID 登录」入口进入登录页。
5. 图片素材只用于纸张背景、角色、装饰和质感；文字、输入框、按钮、Tab 全部用真实 HTML/CSS/JS。
6. 默认语言改为中文，避免裸访问时出现「登录框英文、游戏中文」。

## 三、目标用户流程

### 未登录

```text
进入页面
  -> 检查 localStorage 无用户
  -> 显示身份选择页 identity
      -> 点「我是小朋友」进入 register-child
      -> 点「我是家长」进入 register-guardian
      -> 点「已有 ID 登录」进入 login
```

### 小朋友注册

```text
register-child
  -> 填写水獭昵称
  -> 可点击「随机」填入昵称
  -> 提交 POST /api/users { role: "child", displayName, lang }
  -> 成功后显示生成的 OT-ID
  -> 进入游戏
```

### 家长注册

```text
register-guardian
  -> 填写显示名
  -> 填写邮箱
  -> 前端校验邮箱格式
  -> 提交 POST /api/users { role: "guardian", displayName, email, lang }
  -> 成功后显示生成的 OT-ID，并提示保存
  -> 进入游戏
```

### 已有 ID 登录

```text
login
  -> 输入 OT-ID
  -> GET /api/users/{otterId}
  -> 成功后写入 localStorage
  -> 移除登录浮层，进入游戏
```

## 七、语言策略

当前问题：无 `?lang` 参数时，auth 逻辑读取 `document.documentElement.lang`，而 `index.html` 是 `lang="en"`，导致裸访问默认英文；主应用默认中文，两者不一致。

建议直接改为：

```js
function getLang() {
  const queryLang = new URLSearchParams(location.search).get("lang");
  if (queryLang === "en" || queryLang === "zh") return queryLang;
  return "zh";
}
```

中英文通过 `TEXT.zh` / `TEXT.en` 文案字典控制。同一套 DOM，不做两套页面，不依赖中英文整张效果图切换。

## 十、验收标准

完成后逐项检查：

- 裸访问默认中文。
- 未登录先看到身份选择页。
- 点击「我是小朋友」进入小朋友注册页。
- 点击「我是家长」进入家长注册页。
- 有明显的「已有 ID 登录」入口。
- 小朋友注册只需要昵称。
- 家长注册需要显示名和邮箱。
- 邮箱有前端格式校验。
- 不出现验证码相关 UI。
- 输入框、按钮、Tab 都是真实 DOM，不是整图。
- 图片只作为背景、角色、装饰或质感。
- 中英文共用一套 DOM，通过文案字典切换。
- 注册成功后能得到 OT-ID 并进入游戏。
- 已有 ID 登录后能进入游戏。
- 切换 ID 逻辑不受影响。
- 移动端不横向溢出。
- 控制台没有图片 base64 请求体或 content length 相关错误。

## 十一、暂不纳入本次改造

这些能力留到下一阶段：

- 邮箱验证码。
- 密码或 PIN。
- 找回 ID。
- 家庭成员绑定。
- 家长和孩子账号关系管理。
- 后端鉴权重构。
- 迁移到 React。

## 十二、最终建议

本次最稳的执行方式是：先用状态机重排流程，再用 CSS 复刻纸张注册视觉，最后接入透明底装饰素材。

`design-assets/注册页/` 的 4 张图作为视觉母版；`public/page0/0-1/` 是身份选择页上线素材的主要来源；`public/page0/0-2/` 是注册页上线素材和视觉参考来源。其中输入框、按钮、Tab、文字类图片不应直接承担交互，必须由前端重建。

这样可以在不推倒现有登录注册逻辑的前提下，让入口体验从普通表单升级成完整的 Otterlantis 童话纸张风格，同时保住后端兼容性、移动端适配和后续多语言维护空间。

```text
基于 public/otterlantis-auth.css，把注册登录浮层改成 Otterlantis 纸张弹窗风格。参考 design-assets/注册页 的 4 张 UI 效果图，但不要把整张 UI 图当页面背景。按钮、输入框、Tab、标题、说明文字都必须是 HTML/CSS 渲染。身份选择页做两张可点击角色卡；小朋友注册页和家长注册页做竖版纸张表单；移动端不能横向溢出。
```

验收重点：

- 页面视觉接近效果图。
- 所有输入框和按钮都是真实 DOM。
- 移动端上下排列，不压缩到不可读。

### 第三步：接入拆分素材

```text
把 public/page0/0-1 和 public/page0/0-2 中适合上线的透明底素材接入 auth 浮层。身份选择页使用 0-1 的 parchment-card-bg、header-otter-decoration、role-card-child-bg、role-card-parent-bg、child-otter-full、parent-house。注册页使用 0-2 的 register-bg-paper 和装饰素材。输入框、按钮、Tab、文字类图片只作为视觉参考，不直接作为交互控件。
```

验收重点：

- 素材只承担背景、角色和装饰。
- 不把大图 base64 塞进请求体。
- 图片定位在桌面和移动端都稳定。

## 十四、关键风险与决策表

| 风险 | 当前判断 | 本次决策 |
|---|---|---|
| 登录无密码，输入 OT-ID 即可登录 | 现有产品设计如此，但存在账号被猜中的风险 | 本次不改鉴权，只保留已有 ID 登录入口；后续另开 PIN/找回/绑定方案 |
| 家长邮箱没有验证码 | 后端没有明确验证码接口 | UI 不出现发送验证码、验证码登录等承诺 |
| 中英文维护成本 | 整图维护会导致每次改文案都要重新出图 | 同一套 DOM + 文案字典，图片只做装饰 |
| 图片文字变糊 | 素材里有不少文字图和大画布图 | 上线优先 HTML 文案；文字图只可短期过渡 |
| 大画布透明边界影响定位 | `title-welcome-otterlantis-Chinese.png`、`parent-house.png` 等存在大画布 | 上线前尽量裁切；不能裁切时用 CSS 容器限制显示区域 |
| 移动端变形 | 横版身份页如果强行缩小会不可读 | 小屏改纵向布局，注册页保持表单可读性 |
| 改动触碰 React 主应用 | 注册登录浮层独立于 React | 本次只动 `public/otterlantis-auth.js` 和 `public/otterlantis-auth.css` |
