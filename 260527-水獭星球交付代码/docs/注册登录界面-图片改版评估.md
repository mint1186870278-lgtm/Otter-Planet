# 注册登录界面 · 图片改版评估与落地建议

> 基于 `docs/注册登录界面-现状报告.md` 与当前 `public` 注册页视觉稿评估。  
> 目标：不把完整设计图当作页面图片上线，而是把图片拆成可维护的 UI 组件与透明底装饰素材。

---

## 一、现状判断

当前登录注册系统的技术前提是：注册登录浮层仍是 `public/otterlantis-auth.js` + `public/otterlantis-auth.css` 的原生 JS/CSS 实现，不属于 React 组件。已存现状报告里明确了这一点，也明确了当前只改登录注册浮层时，不必碰 React 主应用。

这次新增的视觉稿整体方向是对的：从原来的普通左右分栏表单，转向更符合 Otterlantis 的“纸张弹窗 + 童话身份选择 + 角色注册卡”风格。视觉语言已经统一到牛皮纸、低多边形水獭、星星、蓝屋、橙蓝身份按钮这一套，比当前代码里的普通表单更适合作为正式入口。

但是这些图不能直接整张作为前端页面使用。原因有三个：

1. 图片里包含大量文字、输入框、按钮和状态切换，这些都需要是真正的 HTML 元素，否则无法输入、无法点击、无法适配多语言，也不利于无障碍和响应式。
2. 视觉稿的文字是图片渲染出来的，局部会有破碎、糊边、语言版本维护成本高的问题。中文、英文不应各维护一整张大图。
3. 当前后端逻辑已经有登录、注册、埋点、localStorage 等功能，改版应该只替换 UI 表现层，不要重写业务逻辑。

结论：采用“视觉稿作为高保真参考，前端重建 UI，图片只保留背景和装饰”的方案。

## 三、逐页评估

### 1. 身份选择页

当前视觉稿优点：

- 纸张弹窗的整体识别度很强，和 Otterlantis 的童话世界观一致。
- 左侧“小朋友”与右侧“家长”的橙蓝对比清楚，适合儿童产品的入口选择。
- 顶部水獭探头、星星、晶石、蓝屋装饰增强了欢迎感。
- 中文版文案“欢迎来到 Otterlantis!”、“开始探索前，先选择你的身份”比英文版更适合当前默认中文主应用。

需要调整的点：

- 当前整图里的文字不适合直接作为图片。标题、说明、卡片标题、按钮都要改成真实文字。
- 两个身份卡不能作为一整张按钮图，要拆成两个可点击卡片组件。
- 卡片中的水獭、蓝屋可以作为透明底 PNG 装饰，但卡片底色、圆角、阴影、箭头按钮都应由 CSS 实现。
- 中英文版本不能维护两张整图，否则后续任何文案修改都要重新生图。

建议落地结构：

```text
AuthOverlay
└── IdentitySelectPanel
    ├── PaperShell
    ├── TopOtterDecor
    ├── TitleBlock
    └── RoleCards
        ├── RoleCard child
        └── RoleCard guardian
```

页面逻辑：

- 无 localStorage 用户时，默认先进入身份选择页。
- 点击“小朋友”进入 child 注册页。
- 点击“家长”进入 guardian 登录/注册页。
- 保留一个“已有 ID 登录”的入口，避免老用户找不到登录。

---

### 2. 小朋友注册页

当前视觉稿优点：

- “注册勇敢的水獭 ID”的主标题很清楚，和小朋友身份绑定明确。
- 顶部 Tab 状态表达直观：橙色代表当前选择“小朋友”，蓝色代表另一身份。
- 只让小朋友填昵称，符合低门槛注册。
- “随机”按钮是一个适合儿童产品的轻功能，可以提升趣味性。

需要调整的点：

- 输入框必须是真正的 `<input>`，不能嵌在图片里。
- “随机”按钮应是独立 button，点击后填入预设昵称。
- 文案“不要使用真实姓名哦”需要保留，这是儿童隐私提示。
- 主标题旁边的装饰、标题纹理不宜图片化，前端用字体和色彩处理即可。
- 顶部水獭插画可以保留，但不要和纸张背景合成在一张图里，方便移动端裁切。

建议落地字段：

```js
role: "child"
displayName: childNickname
email: undefined
lang: getLang()
```

建议交互：

- 昵称为空时不提交，并给出温和提示。
- 点击“随机”填入昵称，不立即提交。
- 提交成功后显示生成的 OT-ID，再进入游戏或允许复制 ID。
- 仍沿用当前 `POST /api/users`，避免扩大后端改动。

---

### 3. 家长注册页

当前视觉稿优点：

- 蓝屋和家长身份的关联清楚，比单纯文字表单更有记忆点。
- “注册家长 ID”定位明确。
- 表单字段与当前后端设计匹配：显示名 + 邮箱。
- 橙色主按钮和整体品牌色一致。

需要调整的点：

- 当前家长注册实际上仍是半成品：邮箱只记录，不验证码验证。界面文案不能暗示已经完成验证能力。
- “第一版先记录家长邮箱账号；验证码验证可在下一步接入。”这类说明可以保留，但要写得更自然，不要让用户误以为下一步一定会马上收到验证码。
- 邮箱输入框至少要做前端格式校验。
- 需要补一个“已有家长 ID？登录”的入口，否则家长重复注册概率很高。
- 顶部身份 Tab 的 active 状态要和小朋友页完全一致，只是左右高亮切换。

建议落地字段：

```js
role: "guardian"
displayName: guardianName
email: guardianEmail
lang: getLang()
```

建议交互：

- 显示名为空：提示填写显示名。
- 邮箱为空或格式不合法：提示填写有效邮箱。
- 提交成功后显示家长 OT-ID，并提示保存。
- 若后端没有邮箱验证码端点，前端不要出现“发送验证码”“验证码登录”等功能。

## 六、与现有逻辑的兼容方式

现有报告里提到的后端接口可以继续沿用：

- 登录：`GET /api/users/{otterId}`
- 注册：`POST /api/users { role, displayName, email?, lang }`
- 埋点：`POST /api/track`

这次改版属于视觉和流程调整，不需要新增后端接口。唯一要注意的是家长邮箱验证不要在 UI 上承诺，因为当前后端没有明确验证码接口。

建议保留现有 localStorage key：

- `otterlantis_user`
- `otterlantis_session_id`

建议保留现有埋点事件，并补充区分入口：

```js
auth_identity_select_view
auth_role_select_child
auth_role_select_guardian
```

如果不想改埋点协议，也可以先只复用现有 `auth_modal_view`、`auth_register_open`、`user_create`。

## 七、语言问题必须顺手修

现状报告里提到：`index.html` 默认 `lang="en"`，但 React 主应用默认中文，导致裸访问时登录框英文、游戏中文。

这次改版建议直接统一：

```js
function getLang() {
  const queryLang = new URLSearchParams(location.search).get("lang");
  if (queryLang === "en" || queryLang === "zh") return queryLang;
  return "zh";
}
```

视觉稿以中文版为主，英文版只作为 `TEXT.en` 文案字典。不要再用两张不同语言整图解决语言问题。

## 八、推荐改版方案

推荐做法是“低风险视觉重做 + 小流程调整”。

### 保留

- 原生 JS 浮层架构
- 现有 API 调用
- 现有 localStorage
- 现有登录能力
- 当前 child / guardian 两种 role
- 注册成功后进入游戏的逻辑

### 改掉

- 默认先显示登录页 → 改成先显示身份选择页
- 原普通卡片表单 → 改成纸张弹窗风格
- 注册区展开式 Tab → 改成独立 child / guardian 注册页
- 图片文字 → 改成真实 HTML 文案
- 大图按钮 → 改成 CSS 卡片 + 独立透明底角色素材
- 默认英文 → 改成默认中文

### 暂不做

- 邮箱验证码
- 密码 / PIN
- React 迁移
- 后端鉴权重构
- 多用户家庭绑定
- 找回 ID

这些属于下一阶段，不要塞进本次视觉改版。

## 九、开发任务拆分

### Task 1：素材拆分

从当前图中拆出：

- 纸张背景：横版、竖版各一张
- 顶部探头水獭
- 小朋友水獭
- 蓝屋 / 家长屋
- 星星晶石装饰
- 小旗子与局部装饰

要求：

- PNG 真透明底
- 不包含文字
- 不包含输入框
- 不包含按钮
- 不包含整张纸上的 UI 元素

### Task 2：重写 Auth Modal 结构

在 `public/otterlantis-auth.js` 中增加 view 状态：

```js
let authView = "identity";
let selectedRole = null;
```

然后按 view 渲染：

- `identity`
- `login`
- `register-child`
- `register-guardian`
- `created`

### Task 3：重写 CSS

在 `public/otterlantis-auth.css` 中新增纸张弹窗、角色卡、注册页样式。旧的品牌左栏 + 右侧表单布局可以废弃或保留为回滚版本。

### Task 4：接回现有 API

child 注册继续调用：

```js
createUser({ role: "child", displayName, lang })
```

guardian 注册继续调用：

```js
createUser({ role: "guardian", displayName, email, lang })
```

登录继续调用：

```js
loginByOtterId(otterId)
```

### Task 5：移动端适配

移动端不要强行缩整张图。建议：

- 身份选择页两个角色卡上下排列
- 纸张背景宽度 `min(94vw, 760px)`
- 注册页表单宽度 `100%`
- 装饰图可缩小或隐藏一部分
- 主按钮高度保持 56px 以上，方便儿童点击

## 十、给代码助手的短任务写法

为避免请求内容过长，不要一次把现状报告、四张图、全部代码和全部需求都塞给代码助手。建议拆成三次任务。

### 第一次：只改结构

```text
阅读 docs/注册登录界面-现状报告.md。只修改 public/otterlantis-auth.js，把 auth 浮层改成 view 状态机：identity、login、register-child、register-guardian、created。暂时不要做复杂视觉，只保证流程能跑通，继续沿用现有 API 和 localStorage。
```

### 第二次：只改样式

```text
基于 public/otterlantis-auth.css，把注册登录浮层改成 Otterlantis 纸张弹窗风格。按钮、输入框、Tab、角色卡都用 CSS 实现，不要把整张设计图当作背景。保持现有 JS class 名和事件逻辑。
```

### 第三次：接入素材

```text
把 public 里的 auth 透明底素材接入注册登录浮层：纸张背景、顶部水獭、小朋友水獭、家长蓝屋、星星晶石装饰。素材只作为装饰图，所有文字、输入框、按钮仍由 HTML/CSS 渲染。
```

## 十一、验收标准

完成后检查以下几点：

- 裸访问默认中文，不再出现登录框英文、游戏中文的问题。
- 未登录时先看到身份选择页，而不是旧登录表单。
- 点击“小朋友”进入小朋友注册页。
- 点击“家长”进入家长注册页。
- 已有 ID 用户能找到登录入口。
- 小朋友注册只需要昵称。
- 家长注册需要显示名和邮箱，邮箱有前端格式校验。
- 所有输入框都能正常输入。
- 所有按钮都是真实按钮，不是图片。
- 中文和英文切换由文案字典控制，不依赖整张图片。
- 桌面端视觉接近当前设计稿。
- 移动端不溢出、不变形。
- 注册、登录、注册后进入游戏、切换 ID 仍能正常工作。
- 控制台没有 API content length 相关错误。
- 请求体没有塞入大图 base64 或完整设计图数据。

## 十二、最终建议

这批图适合作为“视觉母版”，不适合作为“上线资产”。最稳的落地方式是：

1. 纸张和角色插画保留为透明底素材。
2. 文字、按钮、输入框、Tab 全部前端重建。
3. 保留现有原生 JS 浮层，不迁移 React。
4. 默认入口从登录页改为身份选择页。
5. 当前版本只做视觉与流程重排，不做验证码、密码和家庭绑定。

这样改动范围可控，视觉能明显升级，也不会把注册登录逻辑推倒重来。
