# 跑酷部署回归问题修复方案：加载同步 / 引导跳转 / 星星布点

记录日期：2026-07-04

## 背景

本方案针对当前部署包的 3 个回归问题：

1. 进入跑酷段的“闪闪”方向引导后，第一次按方向会跳回开头，第二次才进入游戏场景。
2. 跑酷场景加载进度页消失，且本地观察到进度页和 3D 场景模型加载不同步。这个页面本来用于遮住 3D 初始化和模型替换过程，必须和真实可见状态同步；同时要避免旧方案卡在某个数字不动。
3. 陆地星星难找。逻辑上只需要 9 颗即可过关，但当前玩家体感像“整个场景只有 9 颗”，很容易因为某些星星不在视野或不在当前地形可达路径上而卡关。

已参考现有文档：

- `docs/首屏加载两分钟性能优化方案.md`
- `docs/跑酷地形低模首包-CDN落地记录.md`
- `docs/跑酷静态地形NavMesh优化方案.md`
- `docs/跑酷静态地形HeightField-NavMesh改进执行方案.md`
- `docs/3D模型压缩优化方案-Meshopt优先.md`
- `docs/3D模型压缩基线记录.md`
- `docs/visual-novel-roadmap.md`
- `docs/visual-novel-step-status.md`

结论：这次不要继续先做“真拆地形包 / CDN 同步”。当前更优先的是把跑酷段的进入状态、加载完成契约和星星可达性修稳。否则继续拆包只会让加载状态更复杂，问题更难定位。

## 当前代码观察

### 1. 跑酷段加载完成条件过早

相关文件：

```text
src/App.tsx
src/components/SectionParkour.tsx
public/otterlantis-loader.js
src/components/ParkourScene.tsx
```

当前 `public/otterlantis-loader.js` 有一个隐式完成条件：

```text
visibleSceneReady = 页面上存在 canvas + 存在 [data-tutorial-direction]
```

`SectionParkour.tsx` 里也有类似轮询：

```text
hasCanvas && hasTutorial -> routeSceneReady = true -> markSceneReady()
```

这个条件只能说明“Canvas 和方向教学按钮已经挂到 DOM”，不能说明完整地形、主角、星星、基础障碍、相机初始帧已经稳定。低模首包加入后，Canvas 可以很早出现，所以加载页会提前消失，露出模型尚未同步的状态。

### 2. `ParkourLoading` 在 render 阶段调用全局 loader

相关文件：

```text
src/App.tsx
```

`ParkourLoading()` 当前在函数体里直接执行：

```text
window.otterParkourLoading?.start?.()
```

这属于 render 阶段副作用。它可能在 React 重渲染、Suspense fallback 切换、nearParkour 门控变化时重复触发全局 overlay 状态。结合 scroll-snap，可能造成第一次点击/按键时页面焦点和 section 状态抖动。

### 3. 闪闪方向引导和页面滚动缺少“进入跑酷锁定”

相关文件：

```text
src/App.tsx
src/components/SectionParkour.tsx
src/components/DirectionTutorialOverlay.tsx
```

`DirectionTutorialOverlay` 的按钮已经 `preventDefault()`，键盘事件也会对方向键 `preventDefault()`。但如果跑酷 section 还没有完全进入稳定态，第一次按键时可能同时触发：

```text
Suspense fallback 退出
全局 loader overlay 移除
Canvas focus
scroll-snap 自动吸附
方向教学内部模拟移动
```

所以第一按跳回开头更像是“页面流转状态未锁定”，而不是方向按钮本身错。

### 4. 星星数据和引导数据不完全一致

相关文件：

```text
src/components/parkourConstants.ts
src/components/parkour/Stars.tsx
src/lib/interactionHints.ts
src/components/SectionParkour.tsx
```

当前 `STAR_POSITIONS` 有 14 颗陆地星，`CREEK_STAR_POSITIONS` 有 9 颗水面星，进度 `TOTAL_STARS = 9` 封顶。

但最近星引导使用的是：

```text
findNearestUncollectedStar(player, STAR_POSITIONS, collectedIds)
```

也就是说，引导只看 `STAR_POSITIONS`，不看运行时传入的 `landOverrides`，也不看 `creekItems`。如果星星视觉位置被调试覆盖、低模/完整地形切换后实际落地有偏差，最近星提示可能指向“数据上的最近星”，不是“玩家真正看得见且可达的星”。

### 5. HeightField 不能直接作为星星最终验收依据

相关文档：

```text
docs/跑酷静态地形HeightField-NavMesh改进执行方案.md
```

文档记录过：角色贴地曾因为出生点 HeightField 高度偏差影响体验，所以角色贴地已暂时恢复完整地形 raycast。星星重新布点时可以用 HeightField 做第一轮候选，但最终必须用实际游戏画面和调试面板验证，不能只靠离线采样。

## 修复优先级

### P0：先稳住进入跑酷和闪闪引导

目标：玩家从第三页进入跑酷后，第一次按方向只推进方向教学，不会跳回开头。

改动建议：

1. `ParkourLoading` 的 `otterParkourLoading.start()` 移到 `useEffect`。
2. 给跑酷 section 增加进入锁定状态：
   - `SectionIntro onComplete -> scrollToSection(3)` 后，直到跑酷 section 进入视口且 `SectionParkour` mount 完成前，不响应新的跨 section 滚动。
   - 跑酷方向教学激活时，临时关闭页面容器的 scroll-snap 或阻止 wheel/touchmove/方向键导致的 section 滚动。
3. `SectionParkour` 启动方向教学前增加一个稳定条件：
   - 当前 section 仍在视口内。
   - loading overlay 已进入“等待场景 ready”状态。
   - Canvas 容器已 focus。
4. `DirectionTutorialOverlay` 保持按钮自身 `preventDefault()`，同时补 `stopPropagation()`，避免 pointer 事件冒泡到外层页面。

验收标准：

```text
1. 从 intro 点击进入跑酷，只出现一次闪闪方向引导。
2. 第一次点击方向按钮 / 第一次按方向键，不回到首页、不回到 intro。
3. 方向教学完成后才进入 playing。
4. 刷新页面、慢网速、快速连点进入跑酷三种情况都不复现跳回开头。
```

回滚方式：

```text
只回滚 P0 中的 scroll lock / snap lock 代码，不影响 3D 模型、出生点、星星坐标。
```

### P1：重建跑酷加载页和真实模型加载的同步契约

目标：加载页不再由“canvas + 教学按钮出现”自动消失，而是由跑酷场景显式报告“可以露出”。

新的 ready 分层：

```text
moduleReady:
SectionParkour chunk 已加载，React 组件可以挂载。

shellReady:
Canvas、灯光、低模地形、主角占位/主角模型、星星系统、方向教学 UI 已可用。

visualReady:
首帧已经渲染，玩家不会看到蓝屏/空场景/模型突然闪出。

fullTerrainReady:
完整 terrain GLB 加载完成并替换低模地形。
```

加载页收起建议：

```text
第一版收起条件 = shellReady + visualReady
不等待 fullTerrainReady
```

原因：完整地形 35.61 MB，等待它会把体验又拉回“长时间挡住”。但收起前必须至少保证低模地形、主角、星星、基本交互都稳定可见。

具体改动建议：

1. 修改 `public/otterlantis-loader.js`：
   - 移除 `visibleSceneReady()` 自动 `completeScene()`。
   - `markSceneReady()` 仍然保留，作为唯一正常完成入口。
   - 保留 XHR/fetch 进度统计，只负责显示进度，不负责判断场景 ready。
2. 修改 `SectionParkour.tsx`：
   - 删除 `hasCanvas && hasTutorial` 作为 ready 的轮询判断。
   - 使用显式状态收集：
     - Canvas created
     - first frame rendered
     - low terrain shell mounted 或 terrain mounted
     - character mounted 或 character fallback mounted
     - stars mounted
     - tutorial overlay mounted
   - 全部满足后再：
     ```text
     setRouteSceneReady(true)
     window.otterParkourLoading.markSceneReady()
     ```
3. 修改 `ParkourScene.tsx`：
   - 增加 `onSceneWarmReady` 回调。
   - 在 R3F 内部用一个轻量 `SceneReadyProbe` 组件，在 `useFrame` 中等 2 帧后回调，避免 Canvas 刚创建但还没真正画出内容。
4. 修改 `LowTerrainShell` / `TerrainModel`：
   - `LowTerrainShell` mount 后可报告 `terrainShellReady`。
   - `TerrainModel` 完整 GLB mount 后可报告 `fullTerrainReady`，但不作为加载页收起硬条件。
5. 超时策略：
   - 8 秒：如果 shellReady 缺某一项，继续显示进度，但文案改为“还在铺路...”。
   - 18 秒：若仍未 ready，显示“网络有点慢，继续等待或刷新”错误态，不自动隐藏遮罩。
   - 30 秒：只在用户点击“继续进入低模模式”时才收起遮罩，不再静默强制 `markSceneReady()`。

避免卡数字策略：

```text
进度条可以平滑推进到 96%。
ready 之前最多显示 96%，不显示 100%。
ready 后从当前数字补到 100%，再淡出。
超时后显示可理解的慢网提示，而不是一直卡 45% / 73% / 98%。
```

验收标准：

```text
1. 慢网速下加载页一直覆盖跑酷 section，不露蓝屏/空场景。
2. 低模地形 + 主角 + 星星 + 教学 UI 至少完成首帧后，加载页才淡出。
3. 完整地形未加载完时，玩家看到低模可玩场景，而不是空背景。
4. 完整地形加载完成后可自然替换，不影响玩家位置和出生点。
5. 进度不会无限卡死；慢网时给明确提示。
```

回滚方式：

```text
保留 public/otterlantis-loader.js 的进度统计，临时恢复旧 markSceneReady 调用点即可。
不要回滚低模首包、CDN helper、HeightField P1/P2。
```

### P2：重新整理陆地星星布点和引导

目标：玩家始终能在当前地形上看到足够多、足够密、可达的星星；收 9 颗即可过关，但场景里应该有明显保险星。

策略：

1. 保持 `TOTAL_STARS = 9`，不改变剧情节奏。
2. 陆地星从当前 14 颗提升到 18-21 颗。
3. 分 3 段布点，每段至少 6 颗：
   - 第 1 段：出生点到 NPC1 前，必须一眼能看到 2-3 颗。
   - 第 2 段：NPC1 到 NPC2，左右交替散落，避免全部压在道路中线。
   - 第 3 段：NPC2 到 NPC3 / 终点前，补足远端星，避免后半段空。
4. 每 8-12 个 z 单位放一颗主路径星，旁边 2-4 个 x 单位放保险星。
5. 第一颗星保留在出生点正前方，且要有最强视觉提示。
6. 星星位置必须避开：
   - NPC 触发半径核心区。
   - 障碍物生成清空区。
   - 树丛和花草密集遮挡区。
   - 地形边缘、河道不可达区域。

引导逻辑同步：

1. 抽出统一的 `getActiveStarItems()`：
   - 使用实际渲染的 land star 坐标。
   - 合并可收集水面星或明确排除水面星，但要统一。
2. `findNearestUncollectedStar()` 改用实际 active star 列表，而不是固定 `STAR_POSITIONS`。
3. `focusStarId` / `guidedStarId` 指向实际可见星。
4. 闲置提示从“最近星”改成“最近且未被遮挡/距离合理的星”，避免指向远处看不见的星。
5. 如果玩家 8 秒没有收集进展，增强提示：
   - 最近星加高光。
   - 屏幕提示“往星星那里走”。
   - 可选：短暂显示方向箭头。

验证方式：

```text
1. 打开 SHOW_COORDS 或调试面板，沿出生点到终点走一遍。
2. 每颗星都确认在完整地形上，不悬空、不埋地、不被树挡死。
3. 收集任意 9 颗都能触发 3/6/9 里程碑。
4. 不收水面星也能通关；只沿主路径走也能至少看到 12 颗陆地星。
5. 第一段 30 秒内能自然收集到 3 颗。
```

回滚方式：

```text
只回滚 src/components/parkourConstants.ts 中 STAR_POSITIONS。
如果引导列表改动异常，先恢复 findNearestUncollectedStar 使用 STAR_POSITIONS。
```

## 不建议这次一起做的事

### 1. 暂不做真拆地形包

原因：

```text
当前加载页 ready 契约还不稳定。
继续拆包会引入更多 ready 状态，问题会更难判断。
```

等 P0/P1 稳定后，再推进：

```text
A 包：低模可玩路径 + 必要碰撞
B 包：完整地貌 / 树 / 花草 / 远景
C 包：剧情后段装饰资源
```

### 2. 暂不让角色贴地重新切回 HeightField

原因：

```text
已有记录显示出生点 HeightField 高度曾采错。
这次用户刚确认出生点恢复正确，不应碰角色出生和贴地逻辑。
```

星星布点可以参考 HeightField，但最终以实际画面验收。

### 3. 暂不把 CDN 当作本次首要修复

CDN 能改善下载速度，但不能解决：

```text
首次按键跳回开头
loader 过早消失
星星不可见/不可达
```

所以 CDN 放在本轮之后。

## 建议执行顺序

```text
P0：修进入跑酷 + 闪闪方向引导首按跳回问题
P1：重建 loader ready 契约，让加载页和低模可玩首帧同步
P2：重布陆地星星 + 统一星星引导列表
P3：打包部署测试
P4：确认真实环境无回归后，再做真拆地形包 / CDN 同步
```

## 最终验收清单

功能：

```text
1. 第三页进入跑酷后，第一次按方向不跳回首页/开头。
2. 跑酷加载页可见，且只在低模可玩场景真实首帧后消失。
3. 慢网速下进度不卡死，有明确慢网提示。
4. 出生点保持当前正确位置。
5. 陆地上至少 18 颗可见可收集星，任意收 9 颗即可通关。
6. 玩家沿主路径不刻意绕路，也能看到足够星星。
```

命令：

```bash
npm run lint
npm run build
npm run report:assets -- --root=dist --top=20
```

人工测试：

```text
1. 本地正常网络走完整流程。
2. Chrome DevTools Slow 3G / Fast 3G 各测一次跑酷进入。
3. 部署环境首次访问清缓存测试。
4. 部署环境二次访问测试，确认缓存后不出现旧 loader 状态残留。
5. 从 intro 快速连点进入跑酷，确认不跳回开头。
```

## 关键风险

1. 如果 `markSceneReady()` 改成唯一完成入口，但场景 ready 回调漏报，会导致加载页一直不退。因此 P1 必须同时做超时错误态和调试日志。
2. 如果星星数量增加但障碍避让仍只看旧 `STAR_POSITIONS`，障碍可能刷到新增星附近。因此新增星后要同步障碍避让使用同一份 active star 列表。
3. 如果用 scroll lock 修 P0，要确保离开跑酷段和进入后续视觉小说时恢复滚动，否则会卡在跑酷 section。

## 推荐先做

先做 P0 + P1，小步打包验证；确认进入和加载页稳定后再做 P2 星星布点。

原因是星星问题需要进入游戏后测试。如果 P0/P1 不稳，星星测试会被加载/跳转问题干扰。
