# 首屏加载两分钟性能优化方案

## 背景判断

当前前端加载约两分钟，初步判断不是单纯后端接口慢，而是首屏/准首屏静态资源体积过大，并且资源直接从 nginx 源站下载，带宽和节点速度不足。

如果 5MB 下载约 8 秒，那么 80MB 下载约 128 秒，和当前两分钟体感基本吻合。

## 已落地改造

### 1. 增加资源体积报告

新增命令：

```bash
npm run report:assets
```

脚本位置：

```text
scripts/report-assets.mjs
```

用于输出 `dist` 总体积、按扩展名聚合体积、Top 50 大文件。

### 2. 移出设计参考图

已将运行时不需要的注册页 UI 效果图从 `public/注册页` 移到：

```text
design-assets/注册页/
```

这类图片只作为设计参考，不再进入 Vite 构建产物。

### 3. 登录注册 PNG 转 WebP

已将 `public/page0` 下 27 张 PNG 转为 WebP，并把源 PNG 归档到：

```text
design-assets/page0-png-source/
```

运行时代码已改为引用 WebP：

```text
public/otterlantis-auth.js
public/otterlantis-auth.css
```

转换效果：

| 目录 | 原 PNG | WebP |
|---|---:|---:|
| `public/page0` | 22.04 MB | 2.44 MB |

### 4. 音频延后加载

`public/otterlantis-audio.js` 已调整为不在首屏立即设置音频 `src` 和自动播放，避免 `.m4a` 抢首屏带宽。

### 5. 静态资源缓存策略

`server.ts` 已增加静态资源缓存：

- `index.html`：不强缓存。
- JS/CSS/GLB/WebP/音频等静态资源：长期缓存，`immutable`。

### 6. 跑酷 GLB 分阶段加载

`src/components/ParkourScene.tsx` 已移除非首屏必需资源的顶层 preload：

- 树、花、灌木
- 假月亮/真月亮
- NPC 批量 preload

`src/components/parkour/Npc.tsx` 已增加 `loadModels` 控制。教程阶段先显示轻量占位体，教程完成后再加载 NPC 模型。

## 仍需处理的关键问题

### P0：部署侧必须做

1. 把 `dist` 里的大静态资源迁到 CDN，不要让用户直接从 nginx 源站下载。
2. CDN/nginx 配置长期缓存，尤其是 `.glb`、`.webp`、`.m4a`。
3. 用浏览器 Performance 导出真实首屏瀑布图，确认首屏是否仍提前下载 35.61MB 地形。

### P1：继续压缩地形 GLB

当前最大单文件仍是：

```text
public/model-site/scene-terrain-opt.glb 35.61 MB
```

建议下一步：

```bash
npx gltf-transform inspect public/model-site/scene-terrain-opt.glb
```

重点检查：

- Meshopt 是否真的生效。
- 内嵌贴图是否过大。
- 是否有重复贴图/未使用材质/未使用 mesh。
- `textureCompress` 是否匹配当前贴图 slot。

目标：将地形首包压到 10-15MB 内，或拆成低模首包 + 细节延迟包。

### P2：进一步懒加载

跑酷目前已经减少导入即 preload，但地形仍是进入跑酷时的最大下载。后续可以拆为：

- 阶段 A：低配地形、主角、星星、基础障碍。
- 阶段 B：NPC、树、花、灌木。
- 阶段 C：月亮、剧情结算、相册资源。
