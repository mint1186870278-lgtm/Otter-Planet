# 水獭星球跑酷场景 — 「跑道式 → 真开放世界」分步改造方案

> 配套现状评估见 [重构评估.md](重构评估.md)。
> 涉及文件：[src/components/ParkourScene.tsx](src/components/ParkourScene.tsx)、[src/components/SectionParkour.tsx](src/components/SectionParkour.tsx)
> 原则：每步**可独立运行、可独立验证**，做完一步确认无误再进下一步，避免一次性大爆改难以定位问题。

## 总体策略

核心思路：**把"世界滚动"翻译成"玩家移动"**。

当前范式是「玩家钉在 z=2.5，世界往 +z 滚」。改造的承重墙是引入**玩家真实世界坐标 `playerPos {x, z}`**——一旦玩家有了真坐标，相机、物体、碰撞都能顺势改为基于世界坐标，原本各处的 `position.z += speed*d` 滚动逻辑随之删除。

落地顺序遵循依赖链：

```
① 玩家坐标系（地基） → ② 相机跟随 → ③ 物体钉到世界固定坐标 → ④ 2D 碰撞 → ⑤ 收尾打磨
```

每一步都建立在前一步之上，前一步不通不进下一步。

## 阶段 ①：玩家真实坐标系（地基，最关键）

**目标**：玩家拥有连续的世界坐标 `{x, z}` 和朝向 `heading`，能在平面上自由走动。**此阶段地形可以先不动**（玩家在原地形上跑也行，甚至先用一块大平面）。

### 改动点
- **新增状态**（SectionParkour）：用 `useRef` 持有 `playerPos = {x, z}` 和 `heading`（弧度）。坐标用 ref 而非 state，避免每帧 setState 重渲染；需要在 React 层读时再 setState 镜像（如 debug 面板）。
- **输入系统重写**（[SectionParkour.tsx:88-128](src/components/SectionParkour.tsx#L88)）：
  - 从「左右切道 `position(-1/0/1)` + 前进 `forwardSpeed`」改为「方向键/WASD → 速度向量」。
  - 保留 `keysHeld` Set 思路，但 `updateSpeed` 产出的是 `{vx, vz}` 而非单一 forwardSpeed。
  - 八向移动：上下控制 z、左右控制 x；或"前进方向 + 转向"二选一（建议先做更简单的"八向世界轴移动"，转向留到阶段⑤）。
- **Character 组件改写**（[ParkourScene.tsx:109-177](src/components/ParkourScene.tsx#L109)）：
  - 接收 `playerPos` ref（替代 `lane`），每帧 `groupRef.current.position.set(playerPos.x, 0, playerPos.z)`。
  - 删除车道 lerp（[:151](src/components/ParkourScene.tsx#L151)）。
  - `rotation` 改为跟随移动朝向（先简单：朝速度向量方向；不动时保持上一朝向）。
  - 跑步动画 play/pause 触发条件：`moving` 改为"速度向量非零"。
- **每帧位移积分**：在某个 `useFrame` 里 `playerPos.x += vx*d; playerPos.z += vz*d`。可放在 Character 内或新建一个 `PlayerController` 组件。

### 暂时保留（本阶段不动）
- 地形仍可滚动，或临时设 `terrainSpeed=0` 让地形静止、只有玩家动——**建议后者**，这样能立刻看出"玩家真的在世界里移动了"。
- 星星/NPC/障碍此刻位置会错乱，正常，下一阶段修。

### 验证
- 玩家能用键盘在平面上前后左右自由走，松手停下，跑步动画正确 play/pause。
- debug 面板把写死的 `PlayerZ: 2.5`（[SectionParkour.tsx:502](src/components/SectionParkour.tsx#L502)）改成读真实 `playerPos`，确认数值随移动连续变化。
- ⚠️ 此时相机还没改，玩家走远会离开画面——预期现象，进阶段②修。

## 阶段 ②：相机跟随

**目标**：相机变成第三人称跟随，玩家走到哪儿镜头跟到哪儿。

### 改动点
- **CameraRig 重写**（[ParkourScene.tsx:436-445](src/components/ParkourScene.tsx#L436)）：
  - 接收 `playerPos`（替代 `laneX`）。
  - `camera.position` = 玩家位置 + 固定偏移（沿用现有手感：高度 ~5.5、身后距离 ~11，即偏移 `{0, 5.5, 11}`）。
  - `camera.lookAt(playerPos.x, ~1, playerPos.z)`（看向玩家，略抬高看头部）。
  - 用 lerp 平滑跟随（保留现有 `lerp(..., d*4)` 的阻尼手感）避免镜头硬跟。
- **初始相机**（[SectionParkour.tsx:472](src/components/SectionParkour.tsx#L472)）：position 可保留作为首帧值，之后由 CameraRig 接管。

### 进阶（可选，或推迟到阶段⑤）
- 若阶段①做了转向，相机偏移需绕 `heading` 旋转，使镜头始终在玩家背后。先做"固定朝向偏移"也能跑，转向跟随作为打磨项。

### 验证
- 玩家朝任意方向走，镜头平滑跟随，玩家始终在画面中心偏下。
- 走到原来会"出画"的位置，现在不再丢失玩家。
- 至此**"玩家真的在开放世界里移动"的核心体验已打通**。

## 阶段 ③：物体钉到世界固定坐标

**目标**：星星、NPC、障碍从"相对玩家滚动"改为"地图上的固定点"，玩家走过去才遇到它们。

### 改动点
- **星星**（[ParkourScene.tsx:187-243](src/components/ParkourScene.tsx#L187)、[:390-409](src/components/ParkourScene.tsx#L390)）：
  - 数据结构 `{lane, z}` → `{x, z}` 世界绝对坐标，`STAR_POSITIONS` 15 颗重新按地图布点。
  - 删除 `StarsGroup` 的滚动 `useFrame`（[:397-401](src/components/ParkourScene.tsx#L397)），改为静态定位。
  - `StaticCollectibleObject` 的 bob 上下浮动保留。
- **NPC**（[ParkourScene.tsx:305-387](src/components/ParkourScene.tsx#L305)）：
  - `NPC_LOCAL_Z` + `sideX` → 每个 NPC 一个世界 `{x, z}`。
  - 删除 `NpcGroup` 的滚动 `useFrame`（[:374-377](src/components/ParkourScene.tsx#L374)）。
  - 删除"passed 后 `visible=false`"逻辑（[:351-354](src/components/ParkourScene.tsx#L351)）——开放世界里 NPC 不该走过就消失。
- **障碍物**（[ParkourScene.tsx:266-302](src/components/ParkourScene.tsx#L266)、[SectionParkour.tsx:143-156](src/components/SectionParkour.tsx#L143)）：
  - 二选一：**(a) 地图固定布置**（推荐，符合开放世界）——预定义障碍坐标列表，删掉定时生成 + 7s 清除 + 滚动；**(b) 玩家周围动态生成**（保留 runner 的随机感）——在玩家前方一定半径生成、走远后回收。
  - 删除 `ObstacleObject` 的滚动（[:282](src/components/ParkourScene.tsx#L282)）。
- **Debug 追踪器**（[ParkourScene.tsx:414-433](src/components/ParkourScene.tsx#L414)）：NPC 既然固定，直接报其静态世界坐标 + 到玩家距离即可，循环逻辑删除。
- **地形**（[ParkourScene.tsx:15-65](src/components/ParkourScene.tsx#L15)）：
  - 删除 `TerrainTile` 滚动 + 循环（[:42-48](src/components/ParkourScene.tsx#L42)），改为一块静态大地图。
  - 若地图比单块大：要么放大单块缩放，要么平铺多块静态 tile（非循环），要么后续做 chunk 加载（大地图才需要，先不做）。

### 验证
- 玩家不动时，星星/NPC/障碍都静止在各自地图位置。
- 玩家走过去，能接近这些物体（碰撞还没改，先肉眼确认位置对）。
- 倒退/绕路再回来，物体还在原位（不再"经过即消失"）。

## 阶段 ④：2D 平面碰撞

**目标**：三处碰撞从"1D z 距离 + 车道匹配"改为"2D 平面距离"。

### 改动点（统一模式）
所有判定改为：`dx=px-ox; dz=pz-oz; if (dx*dx+dz*dz < r*r) { … }`，其中 `(px,pz)` 是玩家世界坐标，`(ox,oz)` 是物体世界坐标。

- **星星收集**（[ParkourScene.tsx:225-236](src/components/ParkourScene.tsx#L225)）：删 `laneRef === item.lane`，半径沿用 `COLLECT_RANGE≈1.2`。
- **障碍命中**（[ParkourScene.tsx:279-293](src/components/ParkourScene.tsx#L279)）：删车道匹配 + z 区间，半径沿用 `HIT_RANGE≈0.8`。注意去掉原来"z 超过就 miss"的单向逻辑——平面里玩家可能绕开，改为"离开半径即不再判定"或保留可重复触发视设计而定。
- **NPC 接近**（[ParkourScene.tsx:343-355](src/components/ParkourScene.tsx#L343)）：删 z 距离，改平面距离，半径沿用 `APPROACH_RANGE≈6`。`onApproach` 回调和上层 A/B/C 星星判断（[SectionParkour.tsx:175-201](src/components/SectionParkour.tsx#L175)）**原样保留**。
- 物体不多时逐帧暴力遍历即可；后续若卡顿再上空间网格。

### 验证
- 走到星星上 → 收集 + 计分 + HUD 进度条更新（复用现有逻辑）。
- 撞到障碍 → 扣星 + 红色 hit flash（复用现有）。
- 走近 NPC → 按星星数触发对话(情况A)/气泡(情况B)/提示(情况C)，三档逻辑正常。
- 从不同方向接近同一物体，判定都成立（验证确实是平面距离而非车道）。

## 风险与提示

- **阶段①是地基**，玩家坐标系设计（ref vs state、世界轴 vs 朝向相对）会影响后续所有阶段，开工前先定清楚。
- **性能**：玩家坐标用 ref 逐帧更新，避免 setState 触发 React 重渲染；只在需要展示时（debug 面板）节流镜像到 state。
- **地形尺寸**是隐藏工作量：当前靠两块循环 tile 制造"无限"，真开放世界需要一张足够大的静态地图，可能要美术侧出新模型或拼接，**非纯代码工作**。
- **逐阶段可玩**：每个阶段结束都应是"能跑起来的半成品"，不要跨阶段同时改多处。
