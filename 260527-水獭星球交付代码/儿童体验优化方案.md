## 📌 问题 1：文字过多，5岁读不懂

### 现状
- 开场介绍文案：`SectionIntro.tsx:9-20`，中文 3 句：
  1. "我来教你怎么玩！用键盘左右键，或者屏幕上的方向按钮，控制水獭左右移动！"（32字）
  2. "你的目标是：收集星星，躲避障碍物，发现神秘的朋友，和他们交谈！"（28字）
  3. "快去吧！碰到的朋友们能给你月亮的线索！"（18字）
- **已经有打字机逐字效果**（`SectionIntro.tsx:43-54`，60ms/字，标点停 300ms）
- **人物已有浮动动画**（`:124-134`，上下飘）
- 配图：单张 `robot.webp` 立绘（闪闪/Sparky）

### 根因
不是"没有逐字"，而是**每句话太长太满**。一句话塞了"键盘左右键+屏幕方向按钮+控制水獭左右移动"三个信息。5岁记不住。

### 方案（中）
1. **拆碎+精简**：把 3 句长句改成 5-6 句短句，每句 ≤12 字、只讲 1 件事。例：
   - "嗨！我是闪闪～" → "我教你玩这个游戏！" → "按这两个键，水獭就会动" → "去捡亮晶晶的星星⭐" → "小心路上的石头！" → "遇到小动物，跟它说说话～"
2. **配合人物动作**：每句切换时给人物一个小动作（指、跳、转身）。现在只有恒定浮动，可在 `lineIndex` 变化时叠加一次性 motion（如指向键盘那句让人物前倾+手指方向）。
3. **配图简化**：开场如果有玩法说明配图，改成绘本风大图标（一颗星、一块石头、一个对话气泡），别用文字密集的说明。
4. （可选）**语音念出来**：对标"需要V姐讲给他听"，给开场每句配 TTS 音频或预录语音，自动播放。这是最贴合反馈的，但要音频资源，属重改。

## 📌 问题 2：进跑酷马上迷失（核心）

### 现状
- 进游戏引导现在有 3 处，但都偏弱：
  1. **倒计时** 3-2-1-GO（`:913-939`）
  2. **5秒无操作才弹** "往前走探索吧！" + 箭头（`:246-252` 触发，`:942-961` 渲染）—— 要等5秒，且一动就消失（`:256`）
  3. **左下角常驻小卡片**：星星/问号箱/障碍三行图例（`:963-981`）—— 在角落、字小、静态，小朋友不会看
- 没有"你是来找月亮的"这个**目标提醒**，开场说完就再没出现过

### 根因
- 引导是"被动等待"（5秒后才弹）和"角落静态图例"，不符合5岁注意力特点
- **缺少贯穿全程的目标锚点**：小朋友忘了"我为什么在这跑"
- 没有"V姐反复cue"的机制

### 方案（中-重）
1. **进场即给目标**（不等5秒）：倒计时GO之后立刻弹一个大的、居中的目标提示——"找到月亮🌙！先去捡 3 颗星星⭐"，2-3秒后缩到角落常驻。
2. **常驻目标条**：屏幕顶部（星星进度条旁）加一句一直在的"目标：找月亮 🌙"，让小朋友任何时候抬头都知道在干嘛。
3. **闪闪/向导角色贯穿引导**：把左下角静态图例升级成一个**会说话的小助手头像**，在关键节点冒话泡："现在去捡星星！""小心石头！""那边有只鸟，去找它！"。即"V姐反复cue"的产品化。
4. **箭头常驻指向目标**：当前箭头只在卡住时出现。改成始终有个轻微的方向指引（指向下一颗星/下一个NPC）。

> 这条是根问题，建议优先做 1+2（成本可控、见效快），3+4 视时间。

## 📌 问题 3：解锁角色找不到正确的鸟

### 现状
- 集齐3/6/9颗弹中央卡片，**已经有外观线索**："快去找一只红色的鸟吧！"（`:648-660`）
- NPC 位置：`ParkourScene.tsx:413-417`，NPC1在 `(x:20, z:20)`
- 星星位置：`:207-220`，段1星星在 x=-6/6/-4，段2第一颗 x=8
- **问题**：NPC1 的 x=20 偏右，跟附近星星在屏幕上容易挤在一起；卡片关掉后没有任何**持续指向**那只鸟的视觉强引导，小朋友凭一句"红色的鸟"在画面里找不到

### 根因
线索是"文字描述"（红色的鸟），但5岁需要的是"画面里有个箭头/光圈**指着**那只鸟"。弹窗关掉就断了。

### 方案（中）
1. **目标NPC高亮**：里程碑达成后，给对应NPC加持续的视觉强调——头顶大箭头⬇、脚下光圈、或轻微放大+发光，一直到对话触发为止。
2. **箭头领路**：弹窗关闭后，屏幕边缘出现一个指向该NPC方向的常驻箭头（玩家朝它走箭头跟着转）。
3. **错峰**：让NPC和星星不要在同一屏挤着（调NPC位置或星星位置，拉开视觉间距）。`ParkourScene.tsx:413` 可调NPC坐标。
4. **遮挡**：检查NPC立绘渲染顺序/星星是否盖住鸟，必要时让目标NPC渲染在最上层。

## 📌 问题 4：不知道怎么操作、点哪里

### 现状
- 收集星星=靠近自动触发（`ParkourScene.tsx:236-246`，1.5单位范围内自动collect），**不需要主动操作**，但小朋友不知道"撞上去就行"
- NPC对话框进入下一步=点击（对话完成出"继续▶"按钮 `SectionParkour.tsx:800`）
- 没有手把手的首次操作教学

### 根因
机制本身很简单（自动收集），但**没告诉小朋友**。第一次遇到星星/对话框时，缺一个"现在你点这里/走过去"的即时手指引导。

### 方案（中）
1. **首颗星教学**：第一颗星星附近放一个跳动的手指👆/箭头 + "走过去捡它！"，捡到后消失。只教第一次。
2. **首次对话教学**：第一个对话框出现时，在"继续/说"按钮上加跳动手指 + "点这里"。
3. **按钮更显眼**：对话框的"继续▶""说"按钮加呼吸/跳动动画，吸引点击。
4. 配合问题2的"会说话小助手"，由它来说"走过去就能捡到星星哦"。

## 📌 问题 5：障碍无惩罚、玩法单一

### 现状
- 撞障碍：`SectionParkour.tsx:322-326` —— **只有红屏闪一下，明确注释"不扣星"**。无任何实质惩罚
- 星星累计`只增不减`（`:129`注释）
- 玩法元素：跑 + 自动捡星 + 躲障碍（无后果）+ NPC对话 + 问号箱。比较单一

### 根因
障碍物没有后果 = 没有挑战。小朋友的反馈"没有挑战性"是准确的。

### 方案（重，需权衡）
> ⚠️ 注意：这条和"降低难度让5岁能玩"有张力。惩罚不能太狠，否则小朋友受挫。建议"温和惩罚+正反馈为主"。

1. **温和惩罚**（推荐）：撞障碍 → 短暂眩晕/减速（代码里`:323`已留注释"惩罚改眩晕"的设计意图），或星星进度条抖动+暂时-1（可再捡回）。不要直接清零。
2. **玩法多样**：
   - 星星变化：加一种"金色大星"=值3颗，或会移动的星星
   - 障碍变化：加可跳过/可绕过的不同障碍
   - 加"加速带""磁铁道具（吸附星星）"等正向道具
3. **节奏**：障碍密度随进度递增，给一点点上升的挑战感。

> 这条工作量最大，建议放在 1/2/3/4/8（引导和文案类）之后做。先让小朋友"能玩懂"，再让"好玩"。

## 📌 问题 6：讲故事环节厌烦

### 现状
- 月亮向导 prompt：`SectionVisualNovel.tsx:10-13`（MOON_GUIDE_SYSTEM）
- 要求小朋友复述 **7 个情节点**（出发原因→进森林→啄木鸟→小鸟指错→假月亮→叽里咕噜→真月亮）
- 完成判定：模型觉得"关键情节基本讲到"才给 `[COMPLETE]`（`:199` 检测）
- prompt 规则："每次只提示一个缺失情节、一次只追问一个、不要连环发问"

### 根因
- **7个情节点 = 7个回合**，对5岁太长。"被摁在屏幕前讲故事"非常准确
- prompt 设计成"务必凑齐7点才放行"，模型会反复追问漏掉的点 → V姐和小朋友都"力竭"
- 小朋友说"是的"想快速过，但模型还在逐点引导

### 方案（中，主要改 prompt）
1. **砍情节点**：7点 → 3点核心（如：去找月亮 → 路上遇到朋友 → 找到了真月亮）。其余不追问。
2. **放宽完成判定**：prompt 改成"小朋友讲了**任意1-2个**情节、或表达了'讲完了/是的'，就热情夸奖并给`[COMPLETE]`"。把门槛从"凑齐"改成"参与即通过"。
3. **回合上限**：最多追问 1-2 次，之后无论如何都给 `[COMPLETE]`，避免拖。可在前端加"第N次回复强制显示继续"的兜底。
4. **更短回复**：prompt 现在限50字，可再降到25字，向导话更短。
5. 已有的"跳过对话"按钮（之前加的）此处也适用，是兜底出口。

## 📌 问题 7：NPC对话复杂 + 语音输入 bug

### 现状A — 对话复杂
- 三个NPC prompt：`SectionParkour.tsx:24-30`
  - NPC1 啄木鸟：判断小朋友是否在说"找月亮"
  - NPC2 kiwi：要小朋友**猜名字+给鸟起名**（记忆负担：`[NAME:]`要全程记住）
  - NPC3 叽里咕噜：要小朋友**描述月亮长什么样**
- NPC2 的"起名字并记住"对5岁是额外负担

### 现状B — 语音bug（核心）
- 语音稿同步：`:437-440` `if (srListening) setChatInput(srText)` —— 只在监听时把识别稿覆盖进输入框
- `useSpeechRecognition.start()` 内部会清空 hook 的 text（`finalRef=''; setText('')`）
- **但 `chatInput` 是组件自己的 state**，重新按麦克风时 `chatInput` 不会被清空。新一轮识别第一帧 srText 是空、不覆盖，于是**上一轮的残留稿还留在 chatInput 里**，跟着新识别拼在一起 → "零碎信息全带进来"

### 方案
**B（bug，小修，优先）**：
- 在麦克风按钮 `srStart()` 之前，显式 `setChatInput('')` 清空旧稿。一行修复。
- 位置：`SectionParkour.tsx:780` 附近（voiceStartRef 那个 onClick 的 else 分支，srStart前加清空）。
- 同理检查 SectionVisualNovel 的 recognizedText 是否有同样问题。

**A（降低记忆负担，改prompt）**：
1. NPC2 取消"记住名字"硬要求，或改成"随便说什么都接受、不要求记忆"。
2. 三个NPC统一：**小朋友说任何话都热情接受并通过**，不做"判断对错"。把对话从"考验"变成"打招呼"。
3. 缩短NPC回复字数（现在25-35字 → 15-20字）。

## 📌 问题 8：星星找不全、进度不明显

### 现状
- 总星星 `TOTAL_STARS = 9`（`SectionParkour.tsx:259`）
- 通关需要 `MILESTONES = [3,6,9]`，第三段需要**全部9颗**（`:260`）
- 即 **所需(9) = 总数(9)**，一颗都不能漏，漏了就卡住找不到
- 找不到时有气泡提示"还差N颗"（`:291-305`），但没指明星星在哪
- 进度条：顶部胶囊条+移动星星（`:554-607`），有里程碑刻度

### 根因
- **所需=总数**是设计缺陷：没有容错。9颗必须全捡到，漏1颗就永远差1颗，小朋友满地图找
- 进度条在顶部但可能不够"显眼到5岁会注意"
- 缺少"还有星星没捡"的世界内指引（地图上漏的星星没有高亮/箭头）

### 方案（中）
1. **加容错**（推荐核心改法）：要么
   - (a) 多放星星：总数 12-15 颗，通关仍需 9 颗 → 有冗余，漏几颗也够；或
   - (b) 降所需：总数9，通关需要 6-7 颗。
   让"所需 < 总数"。`:259-260` 调数值即可。
2. **漏星指引**：当玩家在某段卡住（够近但没集齐），给未收集的星星加高亮/箭头/光柱，引导回头捡。
3. **进度条增强**：放大、加"还差N颗⭐"的实时文字在进度条旁，比纯图形直观。
4. **回捡机制**：确保玩家能往回走捡漏的星（确认相机/移动允许回头）。
