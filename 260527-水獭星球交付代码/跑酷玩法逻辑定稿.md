# 水獭星球 · 跑酷玩法逻辑定稿

> 本文档是 SectionParkour 的**纯设计层定稿**，整合了所有讨论结论。
> 无论最终采用「跑道式」还是「真开放世界」实现，这套玩法逻辑通用，是后续所有开发 prompt 的依据。
> 面向用户：6 岁儿童。设计核心原则——**低挫败、强引导、一直往前、零卡关**。

---

## 一、核心循环

整局游戏围绕一个不断重复的循环展开，开场必须把这个循环植入小朋友的心智：

```
收集星星 ⭐ → 找到伙伴 🐦 → 听线索 → 继续冒险 → 再收集 → 再找伙伴 …… → 找到真月亮 🌙
```

故事主线：月亮消失了，万物即将枯萎，水獭出发寻找伙伴帮忙，把月亮找回来。

---

## 二、星星系统（剧情钥匙）

星星的唯一作用是**剧情钥匙**，用来解锁与 NPC 的对话。不承担计分功能。

| 项 | 规则 |
|---|---|
| 性质 | 纯钥匙，**已砍掉分数系统** |
| 数量 | 每段 3 颗，共 9 颗，分三段 |
| 分布 | 第一段在 NPC1 之前，第二段在 NPC2 之前，第三段在 NPC3 之前 |
| 触发依据 | 用「累计收集数」`totalCollected`，**只增不减** |
| 掉星影响 | 掉星不影响触发进度（累计数不回退），避免破坏「集齐 3 颗」的干净逻辑 |
| 跑过头没捡够 | **方案 B**：在玩家前方的路上补生成缺的那几颗星，让小朋友永远不用回头捡星 |

> 设计意图：星星是「往前走自然会捡到」的钥匙，凑够一段就解锁该段 NPC。掉了不回退、跑过头会补，保证小朋友一直往前、不卡关。

---

## 三、障碍物系统

| 项 | 规则 |
|---|---|
| 惩罚方式 | 碰到障碍 → 主角**短暂眩晕 1 秒**，期间不能移动 |
| 反馈 | 眩晕时主角抖动 / 闪烁，给到明确的"撞到了"反馈 |
| 不掉星 | **不再扣星**，避免破坏星星钥匙逻辑 |
| 恢复 | 1 秒后自动恢复正常移动 |

> 设计意图：眩晕是小孩能理解的"添麻烦"惩罚，制造躲避的紧张感，但不影响剧情钥匙，不卡关。

## 四、NPC 触发逻辑

**统一为「走近 NPC 3D 模型触发」**，星星数只决定走近时弹出的内容。

### 触发点
玩家走近 NPC 的 3D 模型（进入触发半径）。

### 三种情况

| 情况 | 条件 | 结果 |
|---|---|---|
| A · 正常对话 | 累计星数 ≥ 要求 **且** 没对话过 | 全屏 2D 立绘完整 AI 对话，对话后标记 `npcXDone` |
| B · 还没集齐 | 累计星数 < 要求 | 头顶气泡「还差 X 颗星星呀！」（3 秒消失，不暂停游戏） |
| C · 重复触发 | 累计星数 ≥ 要求 **且** 已对话过 | 头顶气泡：简短催促台词（hardcode，3 秒消失，不走 AI） |

### NPC 配置

| NPC | 角色 | 触发星数 | 立绘 | 模型 |
|---|---|---|---|---|
| NPC1 | 啄木鸟（潮酷老登） | 累计 ≥ 3 | `/npc-2d/啄木鸟.png` | `/npc-model/啄木鸟a型站姿.glb` |
| NPC2 | kiwi 基维鸟（星际背包客） | 累计 ≥ 6 | `/npc-2d/kiwi 基维鸟.png` | `/npc-model/kiwi_基维鸟.glb` |
| NPC3 | 叽里咕噜（植物学家） | 累计 ≥ 9 | `/npc-2d/叽里咕噜.png` | `/npc-model/叽里咕噜.glb` |

### 重复触发催促台词（hardcode）
- NPC1：「又见面啦老弟！别磨蹭，快往前跑！」
- NPC2：「kiwi！还是你呀！月亮在前面等着呢！」
- NPC3：「根据我的观测，你该继续前进啦！」

## 五、NPC 对话内容（AI 接入）

接入**阶跃星辰 API**，每个 NPC 第一句是 hardcode 开场白，之后走 AI 流程。

### NPC1 · 啄木鸟（意图判断）
- 开场（hardcode）：「诶，你怎么急，去干啥呀？」
- AI 任务：判断小朋友说的话是否和"去找月亮"有关
  - 有关 → 热情鼓励 + 引导去问别人 + `[COMPLETE]`
  - 无关 → 有趣提示，引导说出正确意图，不直接说答案
- 检测 `[COMPLETE]` → 对话结束

### NPC2 · kiwi 基维鸟（猜名字 + 指错路）
- 开场（hardcode）：「你猜猜我是谁？」
- AI 流程：
  1. 无论小朋友说什么名字都接受，回复「没错我就是 [名字]！kiwi！」+ `[NAME:名字]`
  2. 告诉小朋友知道月亮线索，但**故意指错方向**（指向假月亮）+ `[COMPLETE]`
- 检测 `[NAME:xxx]` → 存入 `npc2Name`；检测 `[COMPLETE]` → 结束，触发假月亮过场

### NPC3 · 叽里咕噜（描述月亮）
- 开场（hardcode）：「完成我的小考验，我就告诉你月亮在哪！考验是——说出月亮长什么样！」
- AI 任务：无论小朋友怎么描述月亮都算对，给充满惊喜的情绪反馈 +「真月亮就在前面！跟我来！」+ `[COMPLETE]`
- 检测 `[COMPLETE]` → 结束，引导找到真月亮，进入结算

> 完整 System Prompt 见独立的 NPC Prompt Engineering 文档。

## 六、假月亮过场（NPC2 之后）

NPC2 对话结束后触发：

1. 场景前方出现一个**月亮 3D 物件**
2. 玩家走近 → 弹框 1：「哎呀，这不是月亮嘛！」+ 按钮「再看看呢？」
3. 点击按钮 → 弹框 2：「原来是石子呀！再找找吧！」
4. 关闭后提示去找 NPC3

## 七、提示弹窗

### 集齐一段星星的提示
- 触发：收集满每段第 3 颗星的**瞬间**
- 形式：屏幕中央弹出卡片
- 内容：星星图标 +「太棒了！集齐 3 颗星啦！⭐ 往前跑，去找你的伙伴吧！」+ 橙色「出发」按钮
- 交互：点击关闭，继续跑

### 进度条 HUD
- 胶囊形进度条，金色填充，参考可爱卡通样式（星星图标压在末端）
- 按当前段 collected / 3 显示
- 不显示数字
- 3/6/9 节点处有刻度线，到达节点时抖动 + 发光

## 八、开场理念植入（SectionIntro）

在跑酷开始前的叽里咕噜引导页，台词要把核心循环讲清楚，让小朋友形成「星星 → 伙伴 → 前进」的心智模型：

> 收集星星 → 找到伙伴 → 听线索继续冒险 → 再收集 → 再找伙伴……

---

## 九、结局完整度系统（重玩驱动）

开放世界允许小朋友回头找漏掉的 NPC，但**不强制**。不回头的代价是结局故事书缺页——这是主要的重玩驱动。

| 状态 | 结局表现 |
|---|---|
| 3 个 NPC 全部对话过 | 完整结局，故事书 3 段剧情齐全，画廊 3 张剧照齐全 |
| 漏了某个 NPC | 故事书对应段落**缺页**（灰色 / 问号占位），故事总结缺那段 |

- 检查依据：`npc1Done` / `npc2Done` / `npc3Done`
- 鼓励文案：「这次你错过了和 XX 的相遇，再玩一次，集齐所有伙伴的故事吧！」

> 设计意图：选择权交给小朋友——懒得回去找就承担不完整结局，想要完整故事就再玩一遍。正向激励，不是惩罚性责骂。

## 附：与实现方式的关系

本逻辑在两种实现下的差异点：

| 逻辑点 | 跑道式 | 真开放世界 |
|---|---|---|
| 跑过头没捡够星 | 前方补生成缺的星 | 可回头捡，或前方补星 |
| 走近 NPC | 滚动到身边 | 玩家走进半径 |
| 漏 NPC | 较难发生（单向） | 可能跳过 → 结局缺页 |
| 回头找 NPC | 别扭（世界反向滚） | 自然（自由移动） |

> **结局完整度系统在开放世界下意义最大**——因为开放世界才真正允许"跳过 NPC"这个选择存在。
