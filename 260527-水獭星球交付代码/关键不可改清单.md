## 一、地形（场地模型）

- **地形 GLB 文件**：`public/model-site/scene-terrain-opt.glb`
  - 这是**带小溪 + 山 + 海洋**的新版（46MB，来自 gulu 交接包，2026/06/24）。
  - ⚠️ **绝不能换回旧的无小溪版本**（旧版 5.5MB）。
  - URL 版本戳：`?v=20260624-terrain`（在 ParkourScene.tsx 的 `TERRAIN_URL`）。

- **`TERRAIN_SIZE = 240`** —— ⚠️**不要改这个数来"放大世界"**！
  - 原因：所有星星 / NPC / 散布树 / 花草坐标都**写死在 240 尺度**。
  - 改大它（比如 960）只放大地形网格本身，摆件留在旧的小圈里 →
    树缩成中央小岛、星星悬空、出生点错位。**这是 2026/06/27 踩过的大坑。**
  - 想放大世界 → 改 `ACTOR_SCALE`（见下），不是改 TERRAIN_SIZE。

- **`TERRAIN_X_OFFSET / Y_OFFSET / Z_OFFSET` 全部 = 0**
  - 代码会自动把步道最近端对齐到出生点并抬到脚底高度，不需要手动偏移。

## 二、世界放大 —— 只用 ACTOR_SCALE

- **`ACTOR_SCALE`**（ParkourScene.tsx 顶部）是**唯一**正确的"放大世界"旋钮。
  - 原理：把所有"演员"（主角/星星/NPC/障碍/月亮）整体缩小，世界坐标不变，
    视觉上等价于世界放大 `1/ACTOR_SCALE` 倍。对齐零破坏。
  - 数值越小、世界显得越大：
    - `0.5` = 大 2 倍（最初）
    - `0.25` = 大 4 倍
    - `0.125` = 大 8 倍（2026/06/27 当前值）
  - 移动速度 `PLAYER_SPEED` 已乘了它，缩小后步速同步变慢，跑步不打滑。

## 三、角色动画（T-pose 反复出问题的地方）

- **角色模型**：`public/main-character-other-position/idle.glb`
  - 自带 4 条动画 clip（同一骨架）。
  - clip 索引：**`IDLE_CLIP_INDEX = 1`（站立 ≈4.27s）、`RUN_CLIP_INDEX = 2`（跑步 ≈0.67s）**。
  - 换新文件后若 clip 顺序变了，必须同步改这两个索引。

- **动画加载方式（最终方案=纯权重状态机，2026/06/27）**：
  - **手搓 `AnimationMixer` 直接绑 `scene`**，不用 drei `useAnimations`
    （它绑 groupRef + lazy getter + 自带 useFrame，首帧绑定时序不可控 → "出生即 T-pose、移动后才正常"）。
  - **idle + run 两个 action 都常驻 `play()`**，初始 idle 权重 1 / run 权重 0。
    每帧按 moving 把 run 权重朝目标(1/0) lerp，`idle 权重 = 1 - run 权重`。
    **权重和恒 = 1 → 永远有动画驱动骨骼，绝不 T-pose**；切换是平滑权重过渡。
  - `mixer.update(d)` 在 Character 的 useFrame 末尾手动调。
  - ⚠️ **不要用 `crossFadeTo`**（和时序/自愈互相打架，会把跑步动画弄没）。
  - ⚠️ **不要"只 play idle 不 play run"**（run 首次启动有时序坑）。
  - ⚠️ **绝不用 `cloneSkinned`**（量化骨骼克隆后 PropertyBinding 找不到骨骼 → T-pose）。
  - idle.glb = **22.79MB 不压缩版**（URL `?v=20260627-uncompressed`，压缩版 meshopt 解码有嫌疑）。
  - main.tsx **去掉 `<StrictMode>`**（双调 Effect 停掉 action）。

- **角色上树过滤**（地形跟随射线，Character useFrame 内）：
  - 树干材质用 **`startsWith`** 匹配，不能用精确 `===`！新地形材质带后缀
    （`SpruceTreeTrunk.073` / `Green.002` / `SpruceTreeLeaf.003`）。
  - 排除：`startsWith('SpruceTreeTrunk')`、`=== 'Trunk'`、`startsWith('Green.')`、
    `startsWith('SpruceTreeLeaf')` 且 Y>3（树冠）。
  - ⚠️ **不要排除 `tripo*` 材质**——那是扫描的地形块/河岸/山体，角色要踩在上面，排除会穿地。
  - 根因：树干是圆锥，锥面法线朝上，向下射线能打中、越靠树心越高 → 逐帧爬树。（2026/06/27）

- **`<StrictMode>` 已从 main.tsx 移除** —— ⚠️不要加回来。
  - 原因：dev 下双调用 Effect，会把动画 action 停掉、埋点发双倍。

## 四、已知踩坑 / 注意事项

- **Fast Refresh 失效**：ParkourScene.tsx 同时导出组件和常量（STAR_POSITIONS 等），
  导致改它时 HMR 不能热替换、可能留脏 bundle。**改完 ParkourScene 一定要硬刷新
  `Ctrl+Shift+R`**，必要时重启 dev server。

- **dev server 启动**：`cd 260527-水獭星球交付代码 && npm run dev`，端口 3000。

- **登录系统**：`public/otterlantis-auth.js` + `otterlantis-auth.css`（来自 gulu 包），
  通过 index.html 的 `<script>` 注入，不是 React 组件。强制注册墙。
